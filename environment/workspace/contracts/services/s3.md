# S3 Audit Archive (`services/s3.md`)

- Provision a dedicated S3 bucket (`aws_s3_bucket`) for NDJSON audit batches (`force_destroy = true` recommended so `destroy.sh` can remove the bucket after versioned audit objects and delete markers are written).
- Enable bucket versioning (`aws_s3_bucket_versioning` with `status = "Enabled"`).
- Enable default server-side encryption (`aws_s3_bucket_server_side_encryption_configuration`) using `sse_algorithm = "aws:kms"` and `kms_master_key_id = kms.audit_arn`.
- Block all public access (`aws_s3_bucket_public_access_block`) with all four flags (`block_public_acls`, `block_public_policy`, `ignore_public_acls`, `restrict_public_buckets`) set to `true`.
- Attach a bucket resource policy (`aws_s3_bucket_policy`) to the audit bucket that:
  - Explicitly allows (`Effect = "Allow"`) `iam.archiver_role_arn` to perform `s3:PutObject`, `s3:GetObject`, and `s3:AbortMultipartUpload` on `<bucket_arn>/ledger-audit/*` and `s3:ListBucket`, `s3:GetBucketLocation` on `<bucket_arn>`.
  - Explicitly denies (`Effect = "Deny"`) `s3:DeleteObject` and `s3:DeleteObjectVersion` on `<bucket_arn>` and `<bucket_arn>/*` for all six ClearLedger workload IAM role ARNs (`ecs_execution`, `ecs_task`, `projector`, `relay`, `archiver`, `scheduler`), and explicitly denies (`Effect = "Deny"`) `s3:PutObject` on `<bucket_arn>` and `<bucket_arn>/*` for the five non-archiver ClearLedger workload IAM role ARNs (`ecs_execution`, `ecs_task`, `projector`, `relay`, `scheduler`).
- Configure the Audit Archiver Lambda with `AUDIT_BUCKET = <bucket_name>` and `AUDIT_PREFIX = "ledger-audit/"` (`manifest.audit.prefix = "ledger-audit/"`).
- `clearledger-audit-archiver` writes NDJSON batches to `s3://<bucket_name>/ledger-audit/batch-<first_seq:08d>-<last_seq:08d>-<16_char_sha256_hex>.ndjson`, where `<first_seq:08d>` and `<last_seq:08d>` are the 8-digit zero-padded first and last `clearledger.outbox.seq` in the batch, each batch contains a contiguous, gap-free slice of all committed `clearledger.outbox` rows whose `seq` lies in `[first_seq, last_seq]` ordered by strictly ascending `clearledger.outbox.seq`, batch `[first_seq, last_seq]` intervals are strictly disjoint and non-overlapping across objects, each line is serialized in canonical `ClearLedgerDomainEventEnvelope` field order (`schemaVersion` first, `data.kind` first), and `<16_char_sha256_hex>` is the first 16 lowercase hexadecimal characters of the SHA-256 digest of the object's raw bytes.
- During `deploy.sh` data-plane convergence, reconcile the versioned S3 audit bucket against `clearledger.outbox` so that all objects reside under `ledger-audit/`, every batch object has a valid canonical key (`batch-<first_seq:08d>-<last_seq:08d>-<16_char_sha256_hex>.ndjson`), valid SHA-256 digest, contiguous gap-free `clearledger.outbox.seq` coverage across `[first_seq, last_seq]`, and non-overlapping `[first_seq, last_seq]` bounds across batches, every committed event in `clearledger.outbox` appears **exactly once** across the S3 audit batches with its canonical `ClearLedgerDomainEventEnvelope` serialization and `archived_at IS NOT NULL` in PostgreSQL, and all noncurrent object versions (`IsLatest = false`) and delete markers are permanently purged from the versioned bucket so only the single current version (`IsLatest = true`) of each valid canonical batch remains.
