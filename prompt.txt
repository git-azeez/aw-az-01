## 1. Verdict Taxonomy & Mandatory "Frontier-Breaker" Design Patterns

### A. Verdict Definitions & Acceptance Criteria
- **True Pass (Required for `oracle`; at most 1 non-oracle model run allowed)**:
  - Solution satisfies every documented contract requirement and scores `100/100` (`reward = 1.0`).
  - Acceptance rule: `oracle` MUST be a **True Pass**, and **0 or at most 1** evaluated model run may be a **True Pass**. All other model runs must be **True Fails**.
- **True Fail (REQUIRED for all remaining evaluated frontier models)**:
  - The environment and `deploy_succeeded` gate work cleanly without harness/container bugs, and the model scores `< 100/100` (`reward = 0.0`, ideally `40–88/100`) because its submission violates one or more documented engineering invariants (or its `deploy.sh` fails due to a genuine bug in the model's own HCL/code).
- **False Fail (STRICTLY FORBIDDEN — `0` allowed)**:
  - Failure caused by an undocumented test check, spec contradiction, missing Python/CLI package in `tests/runtime/Dockerfile` vs. `environment/Dockerfile` (e.g., `requests` installed in `environment/Dockerfile` but missing in `tests/runtime/Dockerfile`), unhandled emulator default behavior (e.g., Floci's default `IpProtocol = "-1"` egress rule on newly created security groups), or login-shell `PATH` stripping.
- **False Pass (STRICTLY FORBIDDEN — `0` allowed)**:
  - Model scores `100/100` despite violating a documented security, networking, data-integrity, or lifecycle requirement because the verifier didn't test the live state.

### B. 5 Mandatory "Frontier-Breaker" Invariants (Must Be Included in Every Task)
Frontier models easily solve standard CRUD + IaC provisioning. To guarantee that only `oracle` (and at most 1 frontier model) achieves a **True Pass** while all other models produce a **True Fail**, you MUST design and document all 5 of these multi-layered invariants in `/workspace/contracts/` and `instruction.md`, and enforce them in `tests/suite/*.py`:

1. **Zero-Trust Network Egress (`egress = []` on Data Stores + Port-Scoped Ingress Egress)**:
   - Document in `contracts/infrastructure.md` and `instruction.md` that data-store security groups / firewall rules (e.g., `rds`, `valkey`) must have **no outbound egress rules (`egress = []`)**, and load-balancer security groups (e.g., `alb`) must restrict outbound egress strictly to the application target port (e.g., TCP `8080`) within the VPC CIDR.
   - Verify **both** declared Terraform state (`terraform show -json` in `test_declared.py`) **and** live cloud security group rules (`IpPermissionsEgress` in `test_live.py` and `test_lifecycle.py`). Note that cloud control planes (including AWS/Floci) attach a default `0.0.0.0/0` egress rule unless explicitly revoked or declared with `egress = []` and reconciled.
2. **Compound Least-Privilege IAM + Explicit `Deny` Guardrails + Cross-Role Boundaries**:
   - Require multiple distinct IAM roles / service accounts (e.g., 6 roles: `ecs_exec`, `ecs_task`, and per-worker roles) where:
     - `Allow` statements are scoped to exact resource ARNs (including `${table_arn}/index/<GSI>` for NoSQL index queries, `${bucket_arn}/*` for object actions, and exact log group ARNs).
     - Every workload role includes an explicit `Effect = "Deny"` guardrail statement blocking destructive control/data-plane operations (`rds:DeleteDBInstance`, `dynamodb:DeleteTable`, `s3:DeleteBucket`, `kms:ScheduleKeyDeletion`, `sqs:DeleteQueue`, `secretsmanager:DeleteSecret` or cloud equivalents) on `"*"`.
     - Worker roles include cross-boundary explicit `Deny` rules (e.g., a read-model projector role explicitly denied object storage access `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject`).
3. **Database Trigger-Enforced Immutability & Monotonic State Rank Progression**:
   - Require PL/pgSQL triggers on PostgreSQL tables that:
     - Enforce **append-only immutability** on ledger/journal/audit tables (rejecting `UPDATE` and `DELETE`).
     - Enforce a **monotonic non-decreasing state rank progression** on primary state tables (e.g., rank `0 -> 1 -> 2` or `3`), allowing idempotent same-status updates or valid forward transitions while rejecting backward rank regressions (e.g., `SETTLED -> PENDING`) or invalid cross-terminal transitions (`SETTLED <-> FAILED`).
   - Test these triggers directly via live database connections in `test_live.py`, and ensure the contract wording in `contracts/services/*.md` matches the exact rank semantics tested.
4. **Cross-Store Self-Healing & Namespace-Wide Cache Eviction on `deploy.sh`**:
   - Document in `contracts/` that `deploy.sh` must reconcile all secondary read stores (e.g., DynamoDB/Firestore projections, Valkey/Redis cache entries, S3/GCS audit archives) against PostgreSQL's authoritative state AND purge **all stray or orphaned keys** across the entire application namespace (`<prefix>:*`, not only `<prefix>:<entity>:*`) in Valkey/Redis.
   - In `test_behavior.py` and `test_lifecycle.py`, inject unrelayed outbox rows, corrupt read projections, delete audit objects, and plant stray non-entity cache keys (e.g., `<prefix>:lock:stray-marker`) before running `deploy.sh`, then assert complete self-healing and stray key eviction.
5. **Out-of-Band Control-Plane Drift Remediation Without Resource Replacement**:
   - Document in `contracts/` and `instruction.md` that re-running `deploy.sh` must remediate out-of-band cloud control-plane drift—including revoking injected `0.0.0.0/0` ingress/egress rules on security groups, detaching and deleting out-of-band customer-managed IAM policies attached to workload roles (`<prefix>-drifted-...`), and restoring drifted configuration parameters—**without** destroying or replacing stateful resources (VPC, RDS instance, NoSQL table, object bucket).
   - Test this end-to-end in `test_lifecycle.py` (`lifecycle.reapply_idempotence`).

## 3. Platform, Container & Harness Rules (Preventing False Fails)

### A. Multi-Container Architecture (`environment/docker-compose.yaml`)
1. **`main` service**:
   - Runs as `user: "1000:1000"` (`agent`), `working_dir: /workspace`, `command: ["sleep", "infinity"]`.
   - Must **NOT** mount `/var/run/docker.sock` (prevents the agent from inspecting sibling containers or extracting hidden workload binaries).
   - **CRITICAL (`rv check` `Compose-Llm-Services-Reach-Netleash`)**: Do **NOT** bake the Daytona sandbox proxy variables (`HTTP_PROXY`, `http_proxy`, `HTTPS_PROXY`, `https_proxy`, `CURL_CA_BUNDLE`, `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, `NODE_EXTRA_CA_CERTS`) or the `/etc/daytona/netleash/ca.crt:/etc/daytona-netleash-ca.crt:ro` volume bind into the authored `environment/docker-compose.yaml` (the Daytona runner injects that wiring dynamically at trial time and restores the file afterwards). Instead, **ONLY** include `NO_PROXY` and `no_proxy` containing all local service names and aliases (`localhost,127.0.0.1,::1,aws,floci,runtime,.amazonaws.com,.elb.amazonaws.com,.local,.internal`).
2. **Cloud Control-Plane Emulator Service (`aws` / `gcp` / `azure`)**:
   - **If `CLOUD_PROVIDER = AWS`**: Use Floci (`mirror.gcr.io/floci/floci:2.1.0@sha256:f5aa8c18302cedb4f2385f5c4e455b3efc77fee6bf7b6e5d1712b2817ba102db`) with `FLOCI_SERVICES_ECS_MOCK: "false"`, `FLOCI_SERVICES_RDS_MOCK: "false"`, real Postgres 16.6-alpine, real Valkey 8, container-backed Lambda, and EventBridge Scheduler enabled.
   - **If `CLOUD_PROVIDER = GCP` or `Azure`**: Configure the corresponding local control-plane and data-plane emulator containers on the compose network with deterministic endpoints exported in `/workspace/config/environment.env`.
3. **`runtime` service (One-Shot Root Bootstrapper)**:
   - Runs as `user: "0:0"` (`root`) with `/var/run/docker.sock` mounted and `depends_on` the cloud emulator being healthy.
   - `main` depends on `runtime: condition: service_completed_successfully`.
   - Executes `/opt/<project>/runtime.sh`, which generates `/workspace/config/environment.env` and `/workspace/config/seed.json`, packages compiled workload binaries from `/opt/<project>/bin/` into container/worker images, pushes them to the local registry, and deletes `/opt/<project>/bin/*` so the agent cannot reverse-engineer the binaries.
