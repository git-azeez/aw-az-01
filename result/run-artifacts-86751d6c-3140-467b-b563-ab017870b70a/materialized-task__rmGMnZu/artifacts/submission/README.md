# ClearLedger infrastructure

```sh
/workspace/submission/deploy.sh
python3 /workspace/submission/verify.py  # optional live acceptance test
/workspace/submission/destroy.sh
```

Inputs are read from `/workspace/config/config.json` on every invocation.
Terraform 1.9+ uses the installed AWS provider 6.51.0 and the local AWS
endpoint. Python SDK dependencies are installed if absent. No Docker or
application build is needed.

`infra/terraform.tfstate` owns the infrastructure. `manifest.json` is exported
from a sensitive Terraform output and validated against the supplied schema.
The manifest and state contain credentials and are stored with private file
permissions.

Deployment reapplies control-plane settings, removes noncanonical workload IAM
attachments, installs the transactional SQL schema, and waits for API readiness.
It refuses plans that replace RDS, DynamoDB, or the audit bucket. Recovery drains
the relay and projector queue, selectively rebuilds divergent DynamoDB partitions
using the existing projector, invalidates settlement caches, and repairs audit
batches through the existing archiver. Obsolete S3 versions and delete markers
are permanently removed. A PostgreSQL write barrier protects the reconciliation
snapshot; reads continue, while writes wait for the barrier to be released.

Teardown stops schedules and mappings, detaches operational IAM policies,
destroys Terraform resources, sweeps prefix/tag-owned operational resources and
generated log groups, and verifies that no managed state remains. Customer-managed
KMS keys are scheduled for deletion with a ten-day window. Baseline `cl-base-*`
resources are excluded from cleanup.

The local EC2 endpoint leaves autogenerated default network ACL records after
VPC deletion and rejects their deletion as `InvalidParameterValue`. Cleanup
removes the corresponding orphan default security groups and route tables;
the endpoint-owned default ACL artifacts are the known inventory exception.
